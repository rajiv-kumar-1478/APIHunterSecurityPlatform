## 2. Intentional Security Overrides in New Platform

While APIHunterV2 serves as the source of provider validation knowledge, the new Platform strictly overrides APIHunterV2 behaviors with 6 mandatory security invariants:

1. **Server-Controlled Destination**: APIHunterV2 accepts candidate URLs in certain providers. The new Platform strictly forces all validation requests through `ValidationEndpointRegistry`. Candidate-supplied URLs/hosts are rejected.
2. **DNS-Rebinding Protection (`DEC-015`)**: `SocketsHttpHandler.ConnectCallback` pins TCP connection directly to validated IP address, eliminating TOCTOU DNS rebinding while preserving TLS SNI.
3. **Zero Secret Leakage**: APIHunterV2 logs raw response bodies and authorization headers in debug logs and database fields. The new Platform writes ONLY sanitized metadata (`SafeEvidenceJson`). Plaintext secrets are decrypted strictly within memory method scope and discarded immediately.
4. **No Hardcoded Models**: Model choices for inference-capable validators (e.g. Anthropic, OpenAI) are driven by strongly typed configuration (`ValidationPolicyOptions.AnthropicValidationModel`) rather than hardcoded string literals inside validator code.
5. **No Secondary Overt Requests**: APIHunterV2 executes secondary inference or IAM policy enumeration calls. The new Platform relies strictly on primary authentication calls (e.g., `GET /v1/models`, `GET /user`, `STS GetCallerIdentity`, `GET /v3/scopes`) to minimize quota consumption and prevent unwanted side effects.
6. **Immutable Discovery Provenance vs Independent Validation Truth**: APIHunter integer statuses (`1` Valid, `7` ValidNoCredits) remain untouched as immutable historical source information. Validation results are stored on `CredentialValidationResult.Status`.
